# TURZX 控制中心 UI V2 功能与界面规格

状态：已确认并实现  
目标版本：V2  
文档目的：先固定信息架构、功能边界和未来入口，再进行 UI 开发，避免后续每增加一个功能就大幅调整主界面。

## 1. 改版目标

1. 将现有蓝绿色科技风改为黑白简约风格。
2. 软件界面提供“跟随系统 / 浅色 / 深色”三种外观模式。
3. 增加清晰可见的“设置”按钮，所有低频选项集中到设置窗口。
4. 软件界面、按钮、状态、提示框和活动记录统一改为中文。
5. 保留当前已经验证的 USB 协议、屏幕方向和 PNG 传输逻辑，不在 UI 改版中调整底层通信。
6. 提前为图片、动画、自定义屏幕主题和托盘功能预留固定入口；当前图片单张显示已在原入口完成扩展。

## 2. 设计原则

- 黑白为主：不再允许自定义软件强调色，避免界面重新变得杂乱。
- 内容优先：屏幕预览是主视觉，设备状态和“开始/停止”是最高优先级操作。
- 高频操作留在首页：实时监控、亮度和设备重连无需进入设置。
- 低频选项集中：外观、刷新频率、开机启动等统一放入设置窗口。
- 状态不只依赖颜色：连接、运行、错误均同时使用图标、文字和按钮状态表达。
- 软件主题与小屏内容主题相互独立：软件切换深浅色时，不自动改变小屏画面。
- 运行中避免危险切换：USB 正在连续写入时，可能冲突的测试按钮禁用，但“停止实时监控”始终可用。

### 3.3 本次明确不做

- 不更新设备固件。
- 不安装硬件传感器驱动。
- 不修改 WinUSB 驱动。
- 不在本次 UI 改版中实现完整主题编辑器、图片轮播或 GIF 播放。
- 不让软件深浅色模式自动改变小屏仪表盘配色。

## 4. 主窗口信息架构

建议继续使用单主窗口，不引入多页面侧边栏。常用操作数量不多，单窗口更直接；未来功能通过“显示内容模式选择器”和独立设置窗口扩展。

建议尺寸：默认 1180×720，最小 1040×660。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ TURZX 屏幕控制                         ● 已连接      [重新检测]  [⚙ 设置] │
│ 4.6 英寸 · 960×320 · USB                                                │
├───────────────────────────────────────────────────┬─────────────────────────┤
│                                                   │ 显示内容                │
│                                                   │ [系统监控] [图片]       │
│                横版屏幕实时预览                   │ [动画]     [自定义]     │
│                                                   │                         │
│                                                   │ 实时监控                │
│                                                   │ [开始实时监控]          │
│                                                   │                         │
│                                                   │ 屏幕亮度       40%      │
│                                                   │ ───────●────  [应用]   │
├───────────────────────────────────────────────────┴─────────────────────────┤
│ 最近操作：实时画面已发送 · GPU 38°C                         [展开活动记录] │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 顶部栏

- 左侧：产品名“TURZX 屏幕控制”。
- 次级信息：“4.6 英寸 · 960×320 · USB”。
- 右侧：设备状态、重新检测、设置。
- 设备状态文案：`正在检测`、`已连接`、`未连接`、`原厂软件正在占用`、`通信异常`。
- “设置”使用图标加文字，不能只有难以理解的齿轮图标。

### 4.2 屏幕预览卡片

- 占主区域约 68%，保持 3:1 横向预览比例。
- 背景使用纯黑，以准确模拟屏幕边界。
- 左上角标题“屏幕预览”。
- 右上角显示当前内容模式，例如“系统监控”。
- 未连接时仍可离线预览，不以空白替代。

### 4.3 快捷控制卡片

- “显示内容”使用四个等宽模式按钮：系统监控和图片可用；动画、自定义标注“即将支持”。
- 实时监控使用唯一的主按钮，未运行时显示“开始实时监控”，运行时原位变为“停止实时监控”。
- 亮度为横向滑块，右侧实时显示百分比；点击“应用”后写入设备。
- 刷新频率移入设置，不占用首页空间。

### 4.4 底部状态栏与活动记录

- 默认只占一行，显示最近一次重要操作。
- “展开活动记录”打开底部抽屉，高度约 160 px。
- 记录内容中文化，并保留时间戳。
- 活动记录提供“清空”按钮。
- 不再让日志长期占据主界面三分之一空间。

### 4.5 设备测试入口

建议将测试操作放入设置窗口的“设备”分类：

- `发送静态测试画面`
- `运行 12 帧动态测试`
- 动态测试进度条

它们是开发/诊断操作，不应与日常“开始实时监控”拥有同等视觉权重。

## 5. 设置窗口

点击主窗口右上角“⚙ 设置”打开独立设置窗口。建议尺寸 680×560，非全屏，主窗口保持可见。

```text
┌──────────────────────────────────────────────────────┐
│ 设置                                             [×] │
├──────────────┬───────────────────────────────────────┤
│ 外观         │ 外观模式                              │
│ 启动与行为   │ [跟随系统] [浅色] [深色]              │
│ 屏幕         │                                       │
│ 数据         │ 界面预览                              │
│ 设备         │ ┌──────────┐  ┌──────────┐             │
│ 关于         │ │ 浅色示例 │  │ 深色示例 │             │
│              │ └──────────┘  └──────────┘             │
│              │                                       │
│              │ 说明：此选项只改变控制软件外观。       │
├──────────────┴───────────────────────────────────────┤
│                                        [取消] [保存] │
└──────────────────────────────────────────────────────┘
```

### 5.1 外观

- 三段式选择：`跟随系统 / 浅色 / 深色`。
- 默认值：跟随系统。
- 选择后设置窗口立即预览，点击保存后应用到主窗口。
- “跟随系统”保存的是模式本身，不是当时解析出的深/浅结果。
- Windows 改变应用模式时，正在运行的软件自动同步。
- 删除现有“选择强调色”功能及 `AccentArgb` 设置。

### 5.2 启动与行为

- `开机时启动 TURZX 控制中心`：V2 实现。
- `启动后自动开始实时监控`：占位。
- `关闭窗口时最小化到系统托盘`：占位。
- `启动时最小化`：占位。

### 5.3 屏幕

- 刷新频率：500–5000 ms，默认 1000 ms。
- 当前屏幕信息只读：TURZX1.0、960×320、横向反装。
- 屏幕方向：显示当前值并锁定；未来支持其他设备时开放。
- 屏幕布局管理：占位。

### 5.4 数据

- 当前数据源只读：Windows 系统数据、LibreHardwareMonitor、NVIDIA SMI。
- 传感器状态：可用 / 不可用 / 可能需要管理员权限。
- 传感器映射、自定义字段和管理员增强：占位。

### 5.5 设备

- 显示 VID/PID、端点和固件标识。
- `重新检测设备`。
- `发送静态测试画面`。
- `运行动态测试`及进度条。
- 操作仍使用现有安全校验，不提供固件升级入口。

### 5.6 关于

- 软件名称与版本。
- 项目目录和设置文件位置。
- LibreHardwareMonitor 许可证入口。
- 导入/导出设置：占位。

### 6.3 状态颜色策略

推荐“黑白主体 + 极少语义色”：正常状态仍用黑白圆点和文字表达；警告使用低饱和琥珀色小图标；错误使用低饱和红色小图标和错误文字。语义色只占很小面积，不用于按钮边框、卡片或装饰。

### 6.4 排版与组件

- 字体：优先使用“Microsoft YaHei UI”，数字可使用 Segoe UI。
- 标题 22 px；卡片标题 14 px；正文 13–14 px；辅助文字 12 px。
- 统一 8 px 间距基线：8 / 16 / 24 / 32。
- 卡片圆角视觉半径约 8 px；WinForms 若不做复杂自绘，可使用 1 px 边框和留白替代圆角。
- 主按钮高度 40 px，次按钮 36–40 px。
- 不使用渐变、发光、大面积彩色边框或全大写英文标题。
- 图标只使用简单线性图标，并始终配合中文文字。

## 8. 交互状态

### 8.1 启动

1. 加载用户设置。
2. 解析当前软件主题。
3. 立即显示主窗口和离线预览。
4. 后台检测设备。
5. 更新顶部状态，不弹出成功提示框。

### 8.2 实时监控

- 点击开始后按钮原位变为“停止实时监控”。
- USB 测试按钮暂时禁用。
- 亮度按钮默认禁用，避免端点竞争。
- 停止后恢复所有控件。
- 异常时自动停止循环，顶部显示“通信异常”，并在活动记录中给出详细原因。

### 8.3 设置保存

- 主题选项在设置窗口中即时预览。
- 点击“取消”恢复打开设置前的主题。
- 点击“保存”写入设置文件并立即更新主窗口。
- 修改刷新频率时从下一帧开始生效。

### 8.4 未完成功能占位

- 占位按钮可见但不可点击，右上角显示小标签“即将支持”。
- 鼠标悬停显示一句用途说明。
- 不弹出“功能不存在”错误框。
- 占位项不进入键盘 Tab 顺序，避免影响可访问性。

## 9. 设置数据模型

建议将当前 INI 扩展为以下稳定字段：

```ini
ThemeMode=System
RefreshMilliseconds=1000
BrightnessPercent=40
ActivityLogExpanded=False
WindowWidth=1180
WindowHeight=720
```

- `ThemeMode`：`System`、`Light`、`Dark`。
- 旧版 `AccentArgb`：读取时忽略，下一次保存时移除。
- 开机启动仍使用当前用户注册表，不重复保存在 INI。
- 新增字段必须提供默认值，旧设置文件可无损升级。

## 10. 代码结构建议

为降低后续扩展成本，UI 改版时同步拆分职责：

```text
src/Turzx.ControlPanel/
├─ Program.cs
├─ ControlPanelForm.cs          主窗口结构与页面状态
├─ SettingsForm.cs              设置窗口
├─ ControlPanelSettings.cs      设置读写与迁移
├─ AppTheme.cs                  黑白调色板和 ThemeMode
├─ ThemeManager.cs              系统主题检测、切换和控件应用
├─ UiText.cs                    中文文案集中定义
└─ Controls/
   ├─ MonochromeButton.cs       主/次按钮统一样式
   ├─ SettingRow.cs             设置行
   └─ PlaceholderTile.cs        未来功能占位卡片
```

原则：设备通信、协议、遥测和仪表盘渲染继续位于现有独立文件中；设置窗口不得直接操作 USB，所有动作仍由主窗口协调。

## 11. 验收标准

1. 软件启动时默认跟随 Windows 深浅色模式。
2. 三种外观模式可在设置中切换、保存并在重启后保持。
3. Windows 外观变化时，“跟随系统”模式自动同步。
4. 主窗口和设置窗口无残留英文用户文案。
5. 深色与浅色下文字、边框、按钮均有足够对比度。
6. 当前设备检测、静态测试、动态测试、亮度、实时监控功能全部通过回归测试。
7. 小屏画面方向、分辨率和颜色格式不发生变化。
8. 动画、自定义主题等占位不会误触发未完成逻辑。
9. 窗口缩小到最小尺寸后不遮挡主操作按钮。
10. 不安装新驱动、不修改固件。

## 12. 实现顺序

1. 固定设置模型和主题枚举，完成旧配置迁移。
2. 建立黑白主题系统及 Windows 外观监听。
3. 重构主窗口布局，完成所有中文文案。
4. 建立设置窗口和分类导航。
5. 添加未来功能占位控件。
6. 恢复现有按钮事件并执行离线回归测试。
7. 启动软件进行深色/浅色视觉检查。
8. 执行真机连接、亮度、静态、动态和实时监控测试。

## 13. 实现前待确认

1. 软件主题只改变控制软件，不改变小屏仪表盘主题。
2. 主窗口采用“顶部栏 + 大预览 + 右侧快捷控制 + 底部可折叠日志”，不采用左侧多页面导航。
3. 设置采用独立窗口，分类为：外观、启动与行为、屏幕、数据、设备、关于。
4. 删除现有自定义强调色，固定为黑白主题。
5. 允许错误/警告使用极少量低饱和红色/琥珀色，其余界面严格黑白。
6. 原确认项中的图片入口已扩展为单图显示；动画、自定义屏幕主题、托盘、自动监控、导入导出仍为占位。
7. 设备测试从首页主操作区降级到设置 → 设备，但仍完整保留。
